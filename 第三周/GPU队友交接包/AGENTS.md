5. `第二周/第二周实验报告_数据与基准.docx` 与 `pawsx_zh/T4-PAR-中文改写语义一致性/report/M2.md`：冻结数据与判分协议；以第二周的新划分覆盖第一周较早的 validation 用法。
6. `第三周/README.md` 与 `第三周/lab-report-template (1).docx`：本周要求与 Word 四节模板。
7. 原课程包 `pawsx_zh/T4-PAR-中文改写语义一致性/` 的 `题目卡.md`、`README.md`、`manifest.json`、`data/` 与 `oj/` 脚本。

## 硬性要求

- 所有路径相对本包根目录；不得依赖原电脑绝对路径、本机技能、本机缓存或本机虚拟环境。
- 先写 `第三周/M3_执行记录.md`，记录实际设备、环境、任务理解、预计文件变动和各阶段状态；不要等额外确认才开始已授权工作。
- 从原课程包复制出 `第三周/M3_提交包/` 后再实现；原包与 M2 冻结文件保持原字节，`manifest.entry` 指向新增 `oj/run_m3.py`。
- 只读 `data/train.jsonl` 训练；只用 `data/splits/dev1200.jsonl` 选模；`holdout746` 在模型与配置锁定后只评一次；`test_inputs` 与 `compare50` 无标签，只做预测、格式与覆盖率检查。
- 必须真实训练、真实日志、真实逐条预测；禁止伪造指标、伪造训练轨迹、用参考值冒充实测、用测试标签调参。
- 传统轨不调用 LLM 或远端生成 API；推理 `usage.tokens_in/tokens_out/cost/tool_calls` 全为 0；输出每行五键、逐行 flush、失败也保留一行。
- 模型缺失必须明确失败，不得静默下载、回退或重训。
- 报告保留课程四节，数字必须从 `runs/m3/` 保存的预测复算；未执行项如实写“未执行”。
- 未经人工复核不得写“组员已交叉验证”；原分工与实际完成记录分开写。
