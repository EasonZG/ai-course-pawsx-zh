## 二、核心材料

### 2.1 实现思路

- **两层验收**：平台冻结的 `test 400` 是最终门禁（accuracy ≥ 0.6675）；本地再用 `holdout746` 做一次性的留出验收，避免“只在 dev 上调参、最后无法自查”。
- **为什么只切 validation**：`train` 的 44,898 条全部用于训练（再切会损失训练量）；`test_inputs`/`compare50` 没有标签，不能切；`validation` 与 test 同为人工翻译，分布更接近最终切片，适合做本地开发/留出。
- **划分规则**：`dev100` 是课程给定的冒烟集，先整体放进 `dev1200`，保证它不会污染留出集；`dev1200` 的标签配额按 validation 的 56.8 : 43.2 分配（681 / 519），从剩余样本中按标签分层随机抽（seed=0），其余 746 条进 `holdout746`（424 / 322）。
- **冻结方式**：划分文件、规则文件、审计/判分脚本一起写入 SHA-256 清单；`check_benchmark.py` 每次提交前校验，任何改动都会被发现。
- **调参隔离**：`oj/run.py` 新增 `--tune` 参数，默认只读 `data/splits/dev1200.jsonl`；`holdout746` 的标签只由 `eval_split.py` 读取，本周仅用它做一次基准冒烟、没有据此改任何方法，M3 起只在最终评测时读一次。

### 2.2 数据说明

**来源与许可**：`pawsx_zh`，课程清洗版 `course-v1-20261028`；上游为 Google Research 的 PAWS-X 中文子集（<https://github.com/google-research-datasets/paws/tree/master/pawsx>）。上游 LICENSE 允许任何用途，使用时保留署名与声明。格式为 UTF-8 JSONL，每行含 `item_id`、`task`、`text_pair` 和（有标签时的）`target.label`；标签顺序固定为 **0=different、1=paraphrase**。

**数据清洗**：课程已做基础清洗，并按 `metadata.json` 移除 N/S 占位符（validation 16 条、test 25 条）。本周复核：所有切片 `item_id` 唯一、无空文本、标签只出现 0/1；train 内无重复有序句对。除课程既有清洗外，本周**没有删除任何样本**，以保证基准可复现；疑似标注噪声只标记、不修改（见第三节）。

**规模与偏斜**

| 切片 | 条数 | 有标签 | label 0 different | label 1 paraphrase | 最大句长均值 | 句长 ≤64 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| train | 44,898 | 44,898 | 24,409（54.4%） | 20,489（45.6%） | 47.1 | 82.9% |
| validation | 1,946 | 1,946 | 1,105（56.8%） | 841（43.2%） | 44.6 | 88.4% |
| dev100（冒烟） | 100 | 100 | 53 | 47 | 44.9 | 89.0% |
| test_inputs | 1,965 | 0 | — | — | 45.5 | 88.4% |
| compare50（三轨横比） | 50 | 0 | — | — | 40.0 | 96.0% |

**本周新划分**

| 切片 | 条数 | label 0 | label 1 | 用途 | 开发期可用标签 |
| --- | ---: | ---: | ---: | --- | --- |
| dev1200 | 1,200 | 681（56.8%） | 519（43.2%） | 调阈值、早停、提示词/超参、消融选择 | ✅ |
| holdout746 | 746 | 424（56.8%） | 322（43.2%） | 留出验收，只在最后评一次 | 仅判分脚本读 |

**明显偏斜与数据特性**

1. **类别偏斜不算极端，但足以让 accuracy 失真**：多数类 `different` 占 56.8%，全猜它能拿 0.5684；门禁 0.6675 比多数类高 9.9 个百分点，门禁本身有效。但本周实测词面重合基线 accuracy 0.6019 时，`paraphrase` 召回只有 **0.0994**（322 条只抓到 32 条），macro-F1 仅 0.4573——accuracy 比多数类只高 3.4pp，模型实际接近“多数类塌缩”。
2. **高词面重合是这道题的核心难点**：validation 中有 231 条（11.9%）字二元组 Jaccard ≥ 0.8，115 条（5.9%）≥ 0.9；其中 ≥0.95 的 78 条里有 14 条标签为 0。两句完全相同的句对 validation 有 64 条（3.3%），其中 8 条标签为 0；train 有 2,214 条完全相同句对，其中 33 条标签为 0。这些“字面几乎一样、语义却判不同”的样本解释了为什么字面基线只能到 0.56 左右。
3. **句长**：82.9% 的训练句对最长句 ≤64 字，100% ≤128 字；`max_len=64` 会截断约 17% 的训练样本，`max_len=128` 基本不截断。M3 需要把 64/128 作为消融项，而不是直接照搬。
4. **切片重叠（泄漏风险，不能靠划分消除）**：train 与 validation/test **没有**共享句子或句对；但 validation 与 test_inputs 共享 **404 个句子**（占 test 唯一句子的 11.2%），且有 **45 条 test 句对的两句都出现在 validation 中**（2.3%）。`dev100 ⊂ validation`、`compare50 ⊂ test_inputs` 均已确认。结论：本地 `holdout746` 与平台 test 并非完全独立，本地分数只能看方向，最终只认平台 test 400。

### 2.3 判分规则

| 项目 | 规则 |
| --- | --- |
| 输出形状 | 每题一行：`{"item_id": ..., "output": {"label": 0或1}, "status": "ok", "latency_ms": ..., "usage": {...}}` |
| 正确答案 | 单标签 **exact match**：预测整数等于 `target.label` 记 1 分，否则 0 分；0=different，1=paraphrase |
| 可接受写法 | 整数 `0/1`、整数值浮点 `0.0/1.0`、数字字符串 `"0"/"1"` |
| 判非法 | 标签名（`different`/`paraphrase`）、布尔值、越界整数、列表/多答案、空值、无法解析 |
| **多个答案算对几个** | **不给部分分**：单标签题只接受一个 `label`；输出列表或同时给多个答案整题判非法（0 分） |
| 缺行 | 留在分母里记 0 分；覆盖率必须 100% |
| 重复 `item_id` | 整条判无效（不是“最后一条覆盖前面”），记 0 分 |
| 未知 `item_id` | 被忽略，不进入分母 |
| 主指标 | `accuracy` = 正确条数 / gold 总条数（分母恒为 gold 条数，不因缺行/非法输出缩小） |
| 附加指标 | macro-F1、每类 precision/recall/F1、混淆矩阵、valid_output_rate、覆盖率 |
| 置信区间 | 对句对重采样 1,000 次，95% 百分位 bootstrap，seed=0；方法对比用配对重采样，报告 Δaccuracy 的 CI，跨 0 视为无显著差异 |
| 门禁 | 平台冻结 test 400 上 accuracy ≥ **0.6675**，覆盖率 100% |
| 最小有意义差异 | test 400 上 +5.0pp；compare50 只有 50 条，只能可靠检出约 12pp 以上的差异 |

**失败分类**（`eval_split.py` 与报告统一口径）：`false_negative`（gold=1 判 0，漏判改写一致）、`false_positive`（gold=0 判 1）、`format_invalid`、`missing`、`duplicate`、`timeout_error`。

`oj/test_scoring_rules.py` 对以上口径做了 9 条最小测试（全对、缺行、重复、标签名、多答案、bool、越界、数字字符串、未知 ID），当前 **9/9 通过**。

| 方法（holdout746，746 条） | accuracy | 95% CI | macro-F1 | paraphrase 召回 |
| --- | ---: | --- | ---: | ---: |
| 全猜 different（退化基线） | 0.5684 | [0.5335, 0.6032] | 0.3624 | 0.0000 |

## 三、问题分析与改进

1. **accuracy 会掩盖多数类塌缩**。词面基线 accuracy 0.6019，看似比多数类 0.5684 高 3.4pp，但 paraphrase 召回只有 9.9%，macro-F1 0.4573。如果只看 accuracy，会误判“已经接近门禁”。**改进**：判分报告同时给 macro-F1、每类召回和混淆矩阵；模型选择以 dev1200 的 accuracy 为主，但把 paraphrase 召回作为一票否决式的诊断项；M3 尝试类别加权损失或在 dev1200 上校准阈值，观察能否在不掉 accuracy 的前提下把召回拉起来。
2. **高词面重合 + 完全相同句对**。validation 有 64 条两句完全相同的样本，其中 8 条标 0；train 有 2,214 条相同句对，33 条标 0。这些要么是标注噪声，要么是数据构造留下的边界样本，会压低任何模型的上限（validation 约 0.4pp）。**改进**：不删除（冻结基准不因模型好恶改数据），但在错误分析里单列“相同/近相同句对”桶，统计模型在这里的失误；M3 报告必须区分“模型错”与“标签本身可疑”。
3. **验证/测试存在句子级重叠**。validation 与 test 共享 404 个句子（11.2%），45 条 test 句对的两句都出现在 validation（2.3%）。这意味着在 validation 上反复调参可能间接拟合 test 的句子。**改进**：只用 dev1200 调参，holdout746 只评一次；结论只认平台 test 400；报告中明确“本地分数是代理值”。本周已把这条写进冻结声明与判分规则的泄漏约束。
4. **切片太小，点估计不可靠**。dev100 只有 100 条，95% CI 宽约 ±9pp（实测 [0.48, 0.66]）；holdout746 约 ±3.5pp；compare50 只能可靠检出约 12pp 的差异。**改进**：所有差异附 bootstrap 区间；方法对比用配对区间；不根据 compare50 上 1–2 个样本的差异下结论。
5. **原调参脚本会污染留出集**。`oj/run.py` 原来在完整 validation 上网格搜索阈值，而 validation 包含了本周的 holdout746，等于提前看了验收集。**改进**：新增 `--tune` 参数，默认只读 `dev1200`；`check_benchmark.py` 校验划分哈希；冻结后任何改动都会被发现。这是本周最实质的流程修正。
6. **dev100 不是独立证据**。它是 validation 的固定子集，且已全部放进 dev1200，只能做冒烟，不能当泛化证据。**改进**：报告里把 dev100 与 holdout 分栏，禁止用 dev100 分数替代 holdout/test 结论。
7. **本地看不到最终答案**。test_inputs 与 compare50 都没有标签，本地只能验格式与覆盖率，不能算最终 accuracy。**改进**：把平台 test 400 作为唯一门禁；提交前跑 `selfcheck` + `check_benchmark` + `test_scoring_rules`，确保格式、覆盖率、冻结状态都正确。

**下一步（M3）**：① 只用 train 训练、dev1200 选模型，holdout746 最后评一次；② 以 accuracy 为主、macro-F1/paraphrase 召回为诊断，做 max_len 64/128 与类别加权两组消融；③ 错误分析按 Jaccard 分桶（<0.3、0.3–0.6、0.6–0.9、≥0.9）和句长分桶统计；④ 结果写进 `report/M3.md`，数字必须能由 `runs/` 复现。
